## 一、接口事实核实（附来源）

### 1.1 DeepSeek API · 模型名必须是 `deepseek-flash`

| 项 | 值 | 来源 |
|---|---|---|
| 当前正确模型名 | **`deepseek-flash`** | 官方 changelog、Models & Pricing |
| 旧名兼容 | `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍可用，但**请求实际由 V4.1 Flash 处理**，按 Flash 价格计费 | 官方 changelog 2026-09-10 |
| 输入模态 | **text + image（原生多模态）** | 官方模型表 |
| 上下文 | 输入+输出合计 **1,048,576 tokens** | NVIDIA NIM model card |
| 最大输出 | 384K（当前 API 表） | 官方 Models & Pricing |
| 支持特性 | Thinking Mode、JSON Output、Tool Calls、Vision、Responses API、Anthropic API、Chat Prefix Completion、FIM（非思考模式） | 官方模型表 |
| 架构 | MoE，总参 552B / 激活 8B（prefill）、16B（decode） | NVIDIA NIM model card |
| 图片输入方式 | ① Base64 data URL ② 外部 HTTP(S) URL ③ Files API `file_id` | DeepSeek Vision guide |
| 支持格式 | JPEG、PNG、GIF、WebP | DeepSeek Vision guide |

⚠️ **两个坑**
1. **`deepseek-v4-pro` 是纯文本模型**，当前模型表里 input modality 只有 text。**不能拿它做识图。** 识图和文本都走 `deepseek-flash`。
2. NVIDIA 的 NIM model card 写明：vision 配置**支持最多 1,024 image tokens、最小图像面积 295,936 像素**（约 544×544）。→ **图片别过度压缩**，否则可能不达下限。缩图时短边保到 600px 以上比较稳。

来源：
- https://api-docs.deepseek.com/updates
- https://deepseek-usa.ai/guide/deepseek-vision
- https://docs.api.nvidia.com/nim/reference/nvidia-deepseek-v4_1-flash

> 注：本机开发环境的对话本身就跑在 deepseek-v4.1-flash 上。

### 1.2 NapCat + OneBot 11

| 项 | 值 |
|---|---|
| 接入方式 | **反向 WebSocket**：NapCat 主动连到你的服务，如 `ws://127.0.0.1:6701/onebot/v11/ws` |
| HTTP API | 也可开 HTTP，`POST /send_msg` |
| 鉴权 | `access_token` |
| 图片消息段 | `{"type":"image","data":{"file":"...","summary":"...","sub_type":0}}` |
| **表情包** | **`sub_type: 1` 才是表情包**（`0` = 普通图） |
| 图片 file 取值 | 本地路径 / `file://` / `http(s)://` / `base64://` |
| 系统表情 | `{"type":"face","data":{"id":"1-221"}}` |
| 商城表情 | `{"type":"mface","data":{"emoji_id","emoji_package_id","key"}}` |
| 语音 | `{"type":"record","data":{"file":"...silk"}}`，格式 SILK/AMR/MP3 |
| **体积限制** | 图片 **10MB**、视频 100MB、语音 **60 秒** |

来源：
- NapCat 接口文档 http://napcat.apifox.cn/226656652e0
- NapCat Message Handling https://mintlify.wiki/NapNeko/NapCatQQ/guides/message-handling

> 入库表情包时注意 `sub_type=1`，这样在 QQ 里显示才是表情样式而不是普通图片。

### 1.3 一条工程经验

astral-bridge 在出站 QQ 消息前加了 **3~5 秒随机延迟**。我们采纳：出站统一走「随机延迟 → 分条发送 → 打字节奏模拟」，这是"像真人"的最低成本手段。

## 二、6 条需求 → 模块落地映射

| # | 需求 | 实现模块 | 关键设计 |
|---|---|---|---|
| 1 | 感性（抓情绪） | `perceive.py` + `state.py` | 情绪打标结果**写入状态机**（带衰减），不是只塞 prompt |
| 2 | 理性（分析） | `think.py` → `analyze()` | 独立通道，强制 JSON 输出（用 DeepSeek 的 JSON Output 能力） |
| 3 | 主体性 | `persona/` + `autonomy/digest.py` | 持久化人格 + 边界；后台自主浏览；**选择性分享评分器** |
| 4 | 主动说话 | `autonomy/heartbeat.py` + `suppress.py` | 心跳带抖动 + **六层抑制链**；发送前必须重新判断 |
| 5 | 多模态 | `perceive.py` + `sticker.py` + `act.py` | DeepSeek V4.1-Flash 识图 + 本地表情包向量检索 + `sub_type=1` 发送 |
| 6 | 接 QQ | `channel/napcat.py` | OneBot 11 反向 WS，通道层与大脑解耦 |

**统一数据流**

```
NapCat ──OneBot事件──► channel/napcat.py
                          │ 归一化为 Incoming
                          ▼
        perceive.py（情绪打标 + 图片理解）
                          ▼
        state.py（更新情绪/关系/社交电量）
                          ▼
        memory.py（取画像 + 检索情节/情绪记忆）
                          ▼
        think.py（分析通道 → 表达通道）
                          ▼
        act.py（文本 / 表情包 / 语音，带随机延迟）
                          ▼
                    NapCat ──► QQ

并行：autonomy/heartbeat.py 定时唤醒
        → suppress.py 六层判断 → 通过才走 think.py → act.py
        → digest.py 静默浏览 + 写入共有记忆
```

## 三、状态机的数值设计（初版，可调）

**情绪状态**（0~100 或 -100~100）：
| 变量 | 范围 | 衰减 | 说明 |
|---|---|---|---|
| `valence` | -100~100 | 向基线 0 缓慢回归 | 情绪效价：正=开心，负=低落 |
| `arousal` | 0~100 | 向基线 30 回归 | 唤醒度：高=兴奋/激动 |
| `energy` | 0~100 | 每小时 -2 | 社交电量，低时话少 |
| `anxiety` | 0~100 | 有互动时快降、无互动时慢降 | 参考 Bowlby：依恋对象在场 → 焦虑快速衰减 |
| `loneliness` | 0~100 | 有互动时降、无互动时**升** | 与依恋强度正相关 |

**关系状态**（0~100，只增不减为主）：
`trust` / `security` / `intimacy` / `attachment` / `possessiveness`

**基线人格**（来自 `persona.md`，慢变）：`neuroticism` 等大五维度，用于调制事件增量。

> 设计取舍：**初版用「数值 + 衰减 + 事件增量」，不上微分方程。** 微分方程版本（Emergent Psychology Engine 那套）留到阶段 6 再评估——没有日志你根本不知道该调哪个参数。

## 四、六层抑制链（最终版）

```
① 免打扰    当前处于静默时段？（睡觉/上课/深夜）    → 否
② 间隔      距上次主动发言 < N 分钟？               → 否
③ 冷场计数  连续 N 次没得到回复？（≥3 应拉长间隔）  → 否
④ 电量      社交电量 < 阈值？                       → 否
⑤ 有话可说  LLM 判断：现在真有想说的吗？             → 是
⑥ 送出复核  用当前上下文重判，这条现在还成立吗？      → 是
                                                     ↓
                                                允许发送
```

第 ⑥ 层来自 arXiv:2610.05159 的原则：**"到期不等于授权发送"**。定时任务触发只是"提议"，每条消息在真正送出前必须重新判断。

## 五、明确说明：哪些是真实现，哪些是待接入

写代码最容易自欺的地方。**下表如实标注**：

| 模块 | 状态 | 说明 |
|---|---|---|
| DeepSeek 调用（文本+识图） | ✅ 真实可用 | 填 API Key 即通 |
| NapCat 收发（文本/图片/表情包/语音） | ✅ 真实可用 | 需自建 NapCat 并配反向 WS |
| 情绪状态机 | ✅ 真实可用 | 纯本地计算 |
| 三层记忆 + SQLite | ✅ 真实可用 | 向量检索用简单余弦，无需外部服务 |
| 六层抑制链 | ✅ 真实可用 | 纯本地判断 |
| 心跳调度 | ✅ 真实可用 | asyncio 定时 + 抖动 |
| **联网搜索（自主浏览）** | ⚠️ **待接入** | 代码里是 `SearchProvider` 接口 + 抛 `NotConfigured` 的实现。**需要你选一家搜索 API**（Bing / Serper / Tavily / 博查），不填就是明确报错，不会假装搜到结果 |
| 表情包向量检索 | ⚠️ 需先建库 | 检索逻辑真实，但库要靠 `scripts/ingest_stickers.py` 灌入本地表情包 |
| **语音 TTS** | ⚠️ 待接入 | 接口留好，需要你定 TTS 服务（GPT-SoVITS / 阿里 CosyVoice / EdgeTTS） |

**不会做的事**：写一个看起来能跑、实际返回假数据的"联网搜索"。宁可抛错。
