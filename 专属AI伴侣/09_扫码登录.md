# 扫码登录：自动弹出二维码，登录后自动关闭

> 本轮新增。以后打开时**不用再自己去文件夹里找 qrcode.png** 了。

---

## 怎么用

**它本来就在一键启动里** —— 是第 3 步「QQ 通道」的一部分，不是额外动作：

```
[3/3] QQ 通道 NapCat 与扫码登录 ...
      启动中 —— 会弹管理员权限窗口，点「是」
      已在新窗口启动：Vol - QQ通道
      等待 NapCat 就绪 ...
      已登录（小星），不需要扫码
```

没登录时同一步里直接弹窗：

```
[3/3] QQ 通道 NapCat 与扫码登录 ...
      启动中 —— 会弹管理员权限窗口，点「是」
      已在新窗口启动：Vol - QQ通道
      等待 NapCat 就绪 ...
      还没登录 —— 已弹出二维码窗口
      扫码后手机上确认，那个窗口会自己关掉（过期会自动刷新）
```

「拉起 NapCat」和「让它处于已登录状态」被当作同一件事 —— 少一件这步就没做完。

要手动重新弹（二维码过期了、窗口被误关了、或者换号）：双击 **`扫码登录.bat`**。

---

## 那个窗口长什么样

```
┌─────────────────────────────┐
│      等待扫码 …              │   ← 状态会变：二维码已刷新 / 登录成功
│                             │
│      ███ █ ███ █ ███        │   ← 147px 的码放大 3 倍显示（441px）
│      █ █ ██ █ ██ █ █        │
│      ███ ██ █ ███ ██        │
│                             │
│  用手机 QQ 扫码登录 · 二维码约 │
│  2 分钟过期，会自动刷新       │
│  登录成功后这个窗口会自己关掉  │
│                             │
│         [ 关 闭 ]            │
└─────────────────────────────┘
      窗口置顶，居中偏上
```

三种状态：

| 状态 | 显示 |
|---|---|
| 刚打开 | `等待扫码 …` |
| 二维码换了一张 | `二维码已刷新（第 N 次）` |
| 登录成功 | `✅ 登录成功（小星），窗口即将关闭` → 2.5 秒后自动关 |

另外两条防御：

- **旧码不显示**。启动时目录里往往还留着上次登录留下的 `qrcode.png`，那是失效的。
  直接画出来会让人扫一个死码 —— 比什么都不显示更糟。所以超过 150 秒的码不画，
  改成显示「上次的码已经 N 分钟了，等 NapCat 出新码 …」，等 NapCat 写出新的再显示。
- **超时自己收尾**。默认 420 秒还没登录就自己关掉，并在控制台留一句
  「想继续扫码就再跑一次 `扫码登录.bat`」。不设这个的话，窗口会一直在后台轮询接口变成孤儿。

## 为什么不用系统看图器打开那个 PNG

**因为二维码会过期。** NapCat 的登录码大约 2 分钟就失效，它会**重新生成同一个文件**。
系统看图器只是打开了一张静态图片，缓存不清就一直显示旧码 —— 你扫了发现失效，
还得自己重新找文件打开。

所以这里是自己画窗口，**每 2 秒检查文件的修改时间，一变就重新加载**。
扫到过期的码，窗口里会自己变成新的。

---

## 怎么判断「登录成功」

查 NapCat 的 OneBot HTTP 接口（`127.0.0.1:3000`）：

```
get_status       → {"data": {"online": true, ...}}
get_login_info   → {"data": {"user_id": 10001, "nickname": "小星"}}
```

**token 是从 NapCat 的配置里读的，不写死在代码里** —— 以后你在 WebUI 里改了 token 也不用动代码。

```
napcat\**\onebot11_*.json  →  network.httpServers[0]  →  {host, port, token}
```

## 目录与文件

```
vol\扫码登录.bat                     ← 手动弹出二维码（平时用不到）
vol\一键启动.bat                     ← 里面会自动检查登录状态

companion\scripts\
  ├─ napcat_api.py    查 NapCat 的配置/登录状态，找二维码文件（纯标准库）
  ├─ qr_login.py      二维码窗口本体（需要 tkinter）
  └─ show_qr.py       手动入口：找个带 tkinter 的 Python 然后把上面那个拉起来
```

### 为什么要拆成三个

**companion 的 venv 里没有 tkinter。**

tkinter 是标准库里的 C 扩展，**不能 pip 装** —— 它是编译 Python 时就绑定的。
而这个 venv 用的是受管 Python（`~/.workbuddy/binaries/python/`），没带 tkinter。
你系统里的 `C:\Python314\python.exe` 有（Tk 8.6.15）。

所以：

| 文件 | 跑在哪个解释器 | 为什么 |
|---|---|---|
| `napcat_api.py` | 都行 | 纯标准库，谁都能 import |
| `qr_login.py` | **系统 Python**（有 tkinter） | 需要画窗口 |
| `launch_all.py` | venv | 要读 `config.yaml` |

`launch_all.py` **不能**直接 `import qr_login`（会炸在 `import tkinter` 上），
所以查登录状态那段被拆到了 `napcat_api.py` 共用。

`find_tk_python()` 会按顺序找：当前解释器 → `PATH` 上的 python → `C:\Python3*` →
用户目录下的 `Python3*`，逐个试 `import tkinter`，第一个能用就用它。

**找不到会怎样**：退回用系统看图器打开，但会明确告诉你
「**不会自动刷新**，也**不会自动关闭**」。

---

## 顺带说明一个设计取舍

二维码窗口是个**独立进程**（用系统 Python 跑），不是 companion 的一部分。这样：

- companion 崩了不影响它
- 它自己关掉不会牵连任何东西
- 用错解释器也不会污染 venv
