# 对话连贯性与节奏改造

> 本轮（10-13 下午第二轮）的改动。**改完必须重启服务才生效。**

---

## 问题是什么

你提的两条其实是同一个病根：

> 4. 我开启话题后，就算只发一句就退出，vol 也要围绕话题继续展开……现在完全无法持续交互
> 5. 基本是我一句它一句，我两句它两句，**太人机了**，正常对话节奏完全不是这样

原来的设计是「收到一条 → 回一条 → 结束」。下一次要等心跳，而心跳间隔是 20 分钟到 48 小时。
所以体感上就是**问答**，不是**对话**。

真人的对话长这样：
- 你说一句，对方回三句，其中一句是追问
- 你只发了半句就跑去忙了，对方过了一会儿又补一句「对了，刚才那个……」
- 话题聊干了，对方自己起一个新话题
- 但也不会没完没了 —— 连发几条没回应就自己收住

---

## 改动一：活跃会话窗口（解决「说过一句就没了」）

现在多了一个**活跃会话窗口**的概念：

```
你发消息 ──► 进入活跃窗口（默认 15 分钟）
                │
                ├─► 它回复你
                │
                ├─► 隔 25~150 秒（随机），判断「要不要再说一句」
                │       ├─ 有真实的补充/追问 → 说
                │       └─ 只是怕冷场 → 不说
                │
                ├─► 还可以再说，最多连发 3 条没等到回复
                │
                └─► 窗口过期 → 交回那套慢节奏的主动机制（心跳）
```

**每次要开口前都会重新判断一次**，判定为哪一类：

| 类型 | 含义 |
|---|---|
| `more` | 刚才没说完，接着说完（不许重复已说过的） |
| `probe` | 追问一个**一句话就能答**的具体细节 |
| `share` | 想分享一个跟刚才话题有关的东西 |
| `pivot` | 自己起个新话题（她的生活、她看到的事） |
| `stop` | 不说了 |

**三层刹车，防止变成刷屏**：
1. 连续说了 3 条还没等到回复 → 停
2. 同一个话题内最多补 3 次 → 停
3. 深夜（免打扰时段）只允许补 1 条

另外，如果 `stop` 判定为「没什么想说的」，就真的不发。
**不是每条间隔到点都要塞一句话进去** —— 这点很关键，否则就是另一种机械。

## 改动二：真人式多气泡（解决「一整块回复」）

以前是「一条回复 = 一条消息」（超过 120 字才拆）。
现在改成**按句子拆成 1~3 条短消息**，每条之间隔 0.7~2.2 秒发出去。

实测效果：

```
你 > 今天在阿拜多斯那边风沙好大啊，你巡逻累不累

🤖 呜嘿~
🤖 还行，大叔皮糙肉厚的
🤖 就是回去得先洗澡，头发里能抖出半斤沙，风大到连瞌睡都睡不着
```

三条分开发，中间有停顿 —— 这才是打字的感觉。

几个细节：
- **6 个字以下不拆**（拆开会显得神经质）
- **「呜嘿~」这类短前缀会被单独拆出来**（她是星野，这个口癖本来就是独立的一拍）
- 最多 3 条，多出来的合并到最后一条
- 拆完再拼回去必须等于原文（有测试守着，不丢字）

配置在 `config.yaml` 的 `behavior`：`max_chunks`、`split_threshold`、`bubble_delay_ms`。

## 改动三：表情包类图片收不到（你截图里那个）

你截图里它自己说：

> 「前面那张蓝三角的看到了，后面那张白花花一片，啥也没有啊」

**说明普通图片链路已经通了**（蓝三角它真看见了），问题只出在表情包那类。

这轮做了两件事：

**1. 补上 `mface`（QQ 商城表情）的处理。**
以前这种段类型完全没解析 —— 从 QQ 表情面板发的大表情走的就是 `mface`，
OneBot 11 里这类段**没有图片文件**，只有 `emoji_id / package / key / summary`。
现在的处理：先看有没有可用图源，没有就把 `summary` 当文字线索给模型
（「对方发了一个QQ表情包：[敲开心]」），总比什么都没有强。
顺带 `face`（系统小黄脸）也会带出 id 而不只是一个「[表情]」。

**2. 加了媒体段结构日志。**
以后凡是收到带图/表情/语音段的消息，日志里会打印**段结构摘要**（base64 只报长度不报正文）：

```
[channel] 媒体段结构：image{file='/tmp/a.png', base64=128394B, url='https://...'}
```

如果某条消息有图段但没解析出任何来源，会额外警告：

```
[channel] ⚠️ 有图/表情段但没解析出任何图片来源。
```

**下次再出现「看不到图」，把这两行日志发我，就能直接定位。**
是 NapCat 没给图源、还是给了但取不到、还是段类型没覆盖，一看就知道。

## 附二：「为什么我聊天时还在接收群聊的图片」

NapCat 日志里会看到大量这种行：

```
小星 | 接收 <- 群聊 [网络小白·蜜雪罐城(954402631)] [千源泉] [图片]
```

**这不是我们的程序在处理，是 NapCat 在转发。**

NapCat 作为协议客户端，会把它登录的账号**收到的所有消息**都推给本服务（包括你在的每个群）。
我们配的是反向 WebSocket，NapCat 不区分群/私聊，一律上报。

**我们在入口就丢掉了。** `group_mode: off` 时，群消息在 `handle()` 第一行就被 return，
**根本走不到处理管线**。具体来说：

| | 会不会发生 |
|---|---|
| 回复那个群 | ❌ 不会 |
| 下载那张图 | ❌ 不会（所以不花流量、不花 token） |
| 写进记忆 | ❌ 不会 |
| 影响情绪状态 | ❌ 不会 |
| 进对话记录 | ❌ 不会 |
| 看到那段日志 | ✅ 会（NapCat 自己打的，无法关掉，除非调低它的日志级别） |

**有测试守着这一条**：验收测试第 11 段会连发 5 条群消息 + 3 条群里 @ 它 + 2 条群里的图 + 2 条陌生人私聊，
然后断言"不回复 / 情绪没变 / 记忆没变 / 对话记录没变 / 视觉通道没被调用"。

现在启动时和 `/state` 里都会显示：

```
[policy] 注意：NapCat 会把你账号收到的**所有**群消息都转发过来，
         本服务在入口就丢弃（不回复/不下图/不入记忆）
```

```
/state →
  已忽略消息：37 条（群聊策略 off，非主人私聊也不回）
  它们不影响情绪状态，也没进记忆。
```

**⚠️ 一个要留意的点**：如果你以后把某个群加进 `group_allowlist`，
那个群被 @ 时就会**真的开始读图和处理**（验收测试第 12 段验证了这个行为）。
放行前想清楚那个群适不适合。

## 附：搜索服务（第 2 条）

### 先说清楚「为什么 WorkBuddy 能搜、vol 不能」

不是技术不行，是**谁付账**的问题：

| | 谁提供接口 | 谁付账 | 要不要你注册 |
|---|---|---|---|
| WorkBuddy | 平台已接好搜索服务 | 平台 | 不用 |
| vol | 得自己接一家 | 你自己 | **要** |

vol 是跑在你自己机器上的独立程序，它要搜就得自带一份搜索服务的凭证。
而注册账号这件事我做不了——所以之前只能卡在这里。

### 现在有一条完全免注册的路：SearXNG

**SearXNG** 是开源的元搜索引擎：它自己去聚合 Google / Bing / 百度等的结果，
然后暴露一个本地 HTTP JSON 接口。**因为它是你自己的服务，所以不需要任何 key。**

```yaml
search:
  provider: "searx"
  endpoint: "http://127.0.0.1:8888"
```

跑起来的大致步骤（二选一）：

```bash
# 方式一：pip
pip install searxng
# 改 settings.yml：search.formats 加上 json，然后
python -m searx.webapp

# 方式二：Docker
docker run -d -p 8888:8080 searxng/searxng
```

**⚠️ 两个前提**
1. **SearXNG 的 `settings.yml` 必须开 json 格式**，否则我们拿到的是 HTML：
   ```yaml
   search:
     formats:
       - html
       - json
   ```
   这是最常见的坑 —— 代码里专门为它准备了针对性报错，会直接告诉你改哪里。
2. **机器要能出网访问上游引擎**。SearXNG 只是聚合，上游连不上它也没结果。
   如果上游不通，可以在 SearXNG 里只启用国内可达的引擎（Bing CN / 百度 / 360 等）。

### 另外四条备选

| provider | 费用 | 备注 |
|---|---|---|
| `searx` | **完全免费** | 免注册，但要自己跑实例 |
| `google` | 每天 100 次免费 | 要注册，多填一个 `cx` |
| `tavily` | 付费 | 专给 LLM 用的搜索 |
| `serper` | 付费 | Google 结果代理 |
| `bocha` | 付费 | 国内服务 |

google 的两个值：api_key 在 console.cloud.google.com 建（启用 Custom Search API）；
cx 在 programmablesearchengine.google.com 新建（**选「搜索整个网络」**）。

### 五种都验证过什么

- **装配逻辑**：留空 → `NullProvider`；searx **不需要 key** 就能装配；
  google 缺 `cx` 会提示去注册；未知 provider 会报错并列出可选值
- **SearXNG 解析**：用真 HTTP 起了一个假 SearXNG 服务，验证标题/URL/snippet 解析正确
- **最常见的坑**：实例没开 json 格式时，报错会**直接指出**去 `settings.yml` 加 `formats`
- **实例没起来**：给「确认实例在跑、地址填对」的可操作提示，不是一堆栈
- **`endpoint` 没填**：明确提示要填什么

> 四家付费 provider（google/tavily/serper/bocha）的响应结构是**照文档写的、没法实测**
>（我没有它们的账号）。所以代码做了严格校验：结构不符会抛 `SearchResponseError`
> 并打印原始响应，**绝不会静默返回空结果假装搜过了**。

配好之后先自检：

```
.venv\Scripts\python.exe -m scripts.test_search "人工智能 最新进展"
```

## 测试

离线 **148 项** + 阶段 0 验收 **44 项** = **192 项全过**。

新增的测试组：
- **对话连贯性**（13 项）：活跃窗口进出、连发上限刹车、用户回话后重置、
  判定 stop 时不发、电量低收住、窗口过期停止

  `face` 带 id、诊断摘要把 base64 折成长度、非数组型不崩
- 阶段 0 新增一项**真跑**：用户只说一句 → 它回复 → 又自己接了两句 → 按上限收住

## 参数都能调（`config.yaml`）

```yaml
conversation:
  active_window_min: 15            # 想让它陪你聊更久 → 调大
  followup_delay_sec: [25, 150]    # 想让它接得更快 → 调到 [10, 40]
  max_bot_turns_without_reply: 3   # 嫌它话说太多 → 调到 2

behavior:
  max_chunks: 3                    # 想让它一次发更多条 → 调大
  bubble_delay_ms: [700, 2200]     # 气泡之间的停顿
```

`conversation.enabled: false` 可以整个关掉，退回一问一答。
