## 二、启动顺序

### 第 1 步：自检

双击 `vol\preflight.bat`

它会检查依赖 / 配置 / NapCat / 端口 / 表情包库 / 搜索 / TTS，并**真的发一张程序生成的图给 DeepSeek 验证识图能力**，最后列出还差什么。

### 第 2 步：启动伴侣服务

双击 `vol\start_companion.bat`

看到这两行说明服务起来了：
```
[channel] 反向 WS 已监听 0.0.0.0:6701/onebot/v11/ws
[main] 已就绪。Ctrl+C 退出。
```

### 第 3 步：启动 NapCat 并登录 QQ

双击 `vol\start_napcat.bat` → 会弹 UAC 申请管理员权限（**必须**，NapCat 要往 QQ 进程里注入 DLL）→ 然后在弹出的控制台里扫码登录。

⚠️ **务必用 QQ 小号**。这是第三方协议接入，有封号风险，不要拿主力号试。

登录后看伴侣服务的窗口，出现 `[channel] NapCat 已连接` 就是通了。

### 第 4 步：验收

拿你的主号给小号发一条消息，再发一张表情包。预期：
- 小号回复文本
- 发图后它说出图里是什么

### 群聊安全策略（`qq.group_mode`）

| 值 | 行为 |
|---|---|
| **`off`（当前）** | 任何群消息都不回，被 @ 也不回 |
| `mention` | 被 @ 时回。⚠️ 群里**任何成员** @ 它都能让它开口 |
| `allowlist` | 仅 `group_allowlist` 列出的群、且被 @ 时回 |

无论哪种模式，**主动消息永远只发给主人的私聊**，代码里没有往群发消息的路径。

> 为什么默认 `off`：小号 10001 是用户在校使用的号，接入着同学与学校群。
> 先确保它绝不在群里开口，确认无异常后再考虑放行指定群。

`onebot11.json` 路径：
```
vol\napcat\NapCat.52230.Shell\versions\9.9.33-52230\resources\app\napcat\config\onebot11.json
```

> 说明：NapCat 加载配置的顺序是「先找 `onebot11_<QQ号>.json`，没有就用 `onebot11.json` 并保存成前者」。
> 所以现在预置的 `onebot11.json` 会在首次登录后自动派生出带 QQ 号的正式配置，反向 WS 会自动生效，不用再去 WebUI 手点。

## 五、常见问题

**`[channel] NapCat 已连接` 一直不出现**
1. 确认 `start_companion.bat` 的窗口还开着（WS 服务端是它提供的）
2. 确认 NapCat 已登录成功（WebUI 里看得到在线）
3. 检查 token 是否被改过 —— 两边必须完全一致

**发消息没反应**
- 伴侣服务默认**只响应 `qq.owner_id` 的私聊**，其他人在私聊里说话会被忽略（日志有 `[main] 忽略非主人的私聊`）
- 群里必须 **@ 机器人** 才会响应

**图片看不懂**
- `preflight.bat` 的第 6 步会直接验证识图能力，先看那里的结果
- 确认 `llm.model` 是 `deepseek-flash`。**`deepseek-v4-pro` 是纯文本模型，不支持识图**

**表情包发不出去**
- 需要先建库：把表情包放进 `companion/data/stickers/`，然后
  ```
  cd companion
  .venv\Scripts\python.exe -m scripts.ingest_stickers
  ```
- 没建库时不会报错，只是不发图（日志里没有 `[main] 发表情包`）

**NapCat 启动报错找不到 QQ**
- 不要用 NapCat 自带的 `launcher.bat` —— 它是去**注册表**找 QQ 的，而我们这里是便携安装，没有注册表项
- 用 `start_napcat.bat`（内部调 `napcat.bat`，走的是相对路径定位）
