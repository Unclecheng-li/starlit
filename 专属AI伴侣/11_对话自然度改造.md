## 你指出的三个问题，各自的成因

### 问题 1：对话完全由你主导，她不对你好奇、不主动分享

**成因：是我写进提示词里的。**

原来 `persona.md` 的「表达欲」那节写的是：

> **先给反应，再给内容。** 而不是一上来就接对方的话题。
> 例：先「呜嘿~」，或先「这个大叔熟」，再说事。

我只写了「**不要**顺着对方接话」，但**没写「要反问 / 要留话头」**。
模型于是找到了它的最优解：发表感想 → 结束。**你下一句只能自己再找话题。**

换句话说：我把「回应」定义成了终点，而不是半场。

**改法**：在 `persona.md` 新增一节「聊天里的习惯（别把话头全丢给对方）」，
并在 `think.py` 的表达提示词里明写：

- **经常要顺手留个话头**，二选一：反问一句 / 或主动带一件自己的事出来
- 反问要**具体、是你真想知道的那件事**，不是「你今天怎么样」这种客套
- **别每次都用** —— 三四轮里有两三轮带话头就够，句句追问会变成查户口

后面那个「频率限制」很重要。不然它每句都反问，又变成另一种机械。

### 问题 2：「呜嘿~」滥用

**成因有两个，一个是提示词，另一个是拆句逻辑。**

**① 提示词里我把它捧成了万能开头**：

> 例：先「呜嘿~」，或先「这个大叔熟」，再说事。

加上口头禅清单里它排第一，模型就理解成「每句都该用它开头」。

**② 拆句逻辑把「呜嘿~」切成独立一条**：

`act.py` 的 `split()` 遇到波浪号就断句（`_TILDE_MAX_PREFIX = 14`），
所以「呜嘿~在的在的」会被拆成两条发出去 ——
**孤零零一条「呜嘿~」，然后才是正文。这形态看着就像模板。**

**改法**：

- 口头禅那节改成「**很少用**。隔很久才自然冒一次，不是每句都带」，
  并补一句「四条加起来也别连着几条都用」
- 表达提示词里新增一段：「口癖不要每句都用」「**不要一发就是「呜嘿~」单开一条**，
  然后才是正文」「真的想用它时让它自然长在句子里」
- **代码层面**：`split()` 新增一步 —— 开头的短块（≤6 字）**并进下一句**，
  不再单独成条

最后这条是**兜底**：光靠提示词不够，模型总会偶尔写出来，
那就在拆句时把它并掉，保证发出去的形态是对的。

### 问题 3：表情包发得太少

**成因：三处叠加。**

1. **上一轮发过图 → 直接否掉整轮**。结果聊天里只要发过一张，
   后面几轮全被这条拦掉。
2. **概率跟「多久没发」无关**。只有冷却上限，没有「攒势」——
   情绪一高就突然连发，情绪平就一晚上不响。
3. **每次只发一张**。真人经常连甩 2~3 个表情（很好笑/很无语的时候），
   少了这层语气。

**改法**：

- 删掉「上一轮发过就否掉整轮」，改成只拦「上一条正好是纯图」
- 新增**攒势**：距上次发图越久，概率越高（≥10 分钟 ×1.15、≥30 分钟 ×1.35、从没发过 ×1.5）
- 新增 `how_many()`：**62% 一张、28% 两张、10% 三张**，走 `pick_many()` 保证不重复
- 参数从 `base 0.55 / 冷却 20 分` 调到 `base 0.40 / 最小间隔 10 分`
  （**我是用模拟扫出来的，不是拍的** —— 见下面实测）

## 实测对比

### 表情包频率（3 小时 / 60 轮对话）

用**接管 `time.time` 的虚拟时钟**跑真实策略代码（不是我自己复刻的算法）：

| 版本 | 3 小时发出 | 带图轮次 |
|---|---|---|
| 改之前（base0.55 + 25 分冷却 + 上一轮发过就否掉整轮） | **9 张** | 12% |
| 上一版（base0.55 + 20 分冷却） | 10 张 | 13% |
| **现在（base0.40 + 最小间隔 10 分 + 攒势 + 连发）** | **19 张** | **22%** |

约翻倍，而且分布更均匀（不会一晚上不响、也不会突然刷屏）。

### 对话自然度（真调模型，6 轮）

```
你：今天好累啊，什么都不想干
  小星：累就躺着呗，大叔我最有发言权
  小星：刚在翻冰箱，上周买的鱼好像不太行了，闻着怪怪的     ← 主动分享自己的事

你：你中午吃的啥
  小星：中午睡过去了，起来啃了个昨天剩的饭团，凉的
  小星：你图鉴到底看到哪页了，鲸那几页是不是还挺好看的     ← 反问具体细节

你：明天我要出差三天
  小星：三天啊……啧，大叔我最烦收拾行李了，光想想就累
  小星：去哪儿？远的话记得带件厚的，你那边夜里该凉了       ← 反问 + 关心

你：算了不说这些了
  小星：行吧，不想说就不说
  小星：不过「有意思」那事你还没交代呢，大叔我可记着了     ← 记得你没答的问题
  小星：我刚从外面回来，风大得帽子都快飞了                 ← 又分享自己的事
```

| 指标 | 改动前 | 改动后 |

| 「呜嘿~」出现 | 几乎每条都有 | **6 轮里 0 次** |
| 带反问的轮次 | 少 | 2/6（而且都很具体） |
| 自述/主张表达 | 少 | 4 处 |
| 平均长度 | — | 40 字/轮（1~3 条气泡） |

## 测试

离线 **237 项** + 阶段 0 验收 **44 项** = **281 项全过**。

本轮新增：
- **攒势**：刚发过→概率最低、隔 10 分钟→抬升、隔 40 分钟→明显更高、从没发过→进最高档
- **连发张数**：只可能是 1/2/3，且三种都会出现
- **`pick_many`**：不重复、情绪正确、要得比库里多时不报错、没该情绪时返回空
- **拆句**：短感叹词并进下一句（不再单独成条）

**踩的坑（记一下）**：
- 写频率模拟时自己复刻了一遍算法，结果复刻错了（`last` 初始值让 `gap` 算成负数），
  扫出来的数全一样。**改成接管 `time.time` 跑真实代码**才对。
  ——**验行为不要复刻逻辑，直接测原函数。**
- 概率会被 `clamp` 到 1.0，所以测「攒势」的差异时基础概率要压低（我用 0.25），
  否则三档全是 1.000，看不出区别。

## 补充：表情包张数不再写死（并揪出一个更严重的问题）

你指出「张数不该定死，应该按情绪/语境定，但大部分情况要多发」——
对，那个 62%/28%/10% 是我随手拍的。**这个决定最该由模型做，代码只负责兜底和封顶。**

### 改法

| 角色 | 干什么 |
|---|---|
| **模型**（`think.judge_sticker`） | 按语境输出 `count`（1/2/3，强情绪可到 4）和 `emotion` |
| **兜底**（`sticker.how_many`） | 模型漏填时才用，**跟情绪强度走**（不是固定比例） |
| **封顶**（`sticker.clamp_count`） | 收进 `max_per_turn`（默认 4）和**今日余额**之内 |

提示词里还明写了「**你平时偏多**：只要情绪到位就往 2~3 张走。别保守」，
以及「别硬凑：一句话就能带过的平淡回应就 1 张」。

实测（真调模型，7 个场景）：

| 场景 | 发? | 张数 |
|---|---|---|
| 平淡寒暄（"嗯"→"行吧"） | ✓ | **1** |
| 日常闲聊（"中午吃的啥"） | ✓ | **1** |
| 好笑/接梗 | ✓ | **2** |
| 强烈开心（"考试过了！"） | ✓ | **2** |
| 无语/崩溃（"咖啡洒键盘上了"） | ✓ | **2** |
| **对方难过** | ✗ | **0**（正确不发） |
| 得意/被夸 | ✓ | **2** |

张数确实随语境变了，而且以多发为主。

### ★ 但排查过程中挖出一个更严重的问题

上面那张表**第一次跑出来很差** —— 「考试过了！」「新买的鱼缸」居然都不发。
我一开始以为是模型保守，去看了它的**理由**，才发现有两条理由是「**判断失败**」。

追下去，根因是：

```
LLM.chat() 里写的是  return content or ""
                        ↑ 输出被 max_tokens 截断时，静默返回空串
                          → _parse_json_loose 抛异常
                          → 各处兜底吞掉，降级成保守值（"不发"/"中性"）
```

**实测铁证**（同一句话，只改 max_tokens）：

| max_tokens | 返回 |
|---|---|
| 180 | `'{"send": true, "count": 1, "emotion'` ← **被截断**，JSON 不完整 |
| 400 | 86 字符，完整 ✅ |
| 800 | 84 字符，完整，**而且 count 从 1 变成 2** ✅ |

**这是个静默的、影响全局的 bug**：`deepseek-flash` 是推理模型，思维链也算输出 token，
所以各处 `max_tokens` 给 150/180/250 统统不够 —— 表现就是**功能"时好时坏"**，
而且因为 `return content or ""` 把错误吞掉，**日志里什么都看不到**。

**两处修**：

1. `llm.chat()` 现在**显式检查 `finish_reason == "length"`**，是就抛
   「输出被 max_tokens=N 截断（已出 X 字符）」。空返回也抛。
   **不再静默返回半截。**
2. **把所有过小的 `max_tokens` 全部调大**：

| 位置 | 改前 | 改后 |
|---|---|---|
| `think.judge_sticker`（表情包判定） | 180 | **600** |
| `think.decide_followup`（接话判断） | 250 | **600** |
| `think.decide_initiative`（主动开口） | 300 | **700** |
| `perceive`（情绪打标） | 300 | **700** |
| `autonomy.suppress`（发出前复核） | 150 | **600** |
| `autonomy.digest`（速报摘要） | 200 | **800** |
| `think.analyze` | 700 | 700（够） |

顺带说明：**「表情包偏少」里有一份是这个 bug 贡献的** —— 判定 JSON 被截断 → 失败 → 不发。

### 又踩一个坑

我给 mock 的路由条件是 `"要不要配一个表情包" in system`，
而这次改提示词时把措辞改成了「要不要配**表情包**」（少了个"一个"），
**路由直接失配** → 表情包判定被当成表达通道处理 → 验收测试两条挂掉。
已把匹配串改宽，并留了注释提醒。

**提示词措辞和测试 mock 的路由字符串是耦合的**，改措辞时必须同步。

## 第二轮：这两个"依然存在"的问题，根因都找到了

你反馈的两条我都追到了具体成因，**都不是参数问题，是设计/接线问题**。

### 问题 A：还是不问关于我的事

**根因：画像根本没传进表达通道。**

`main.py` 里是这样的：

```python
profile_text=self.memory.profile_text(),   # ← 只传给了 analyze()
...
reply = await express(
    ...
    # 这里没有 profile_text  ← 表达通道拿不到
)
```

**她有你的画像，但写回复的时候看不到。** 所以只能顺着当下的字面聊，
问不出「你那个机器人的事怎么样了」这种话。

举证：我查了数据库，**画像其实有 17 条而且质量很高** ——

```
- 在折腾的东西：虚拟机里跑QQ机器人，会看后台分析日志
- 近期成就：成功让大叔能识别/理解图片，很在意这个进展
- 名字：小白
- 说话习惯：常用"喵"尾音撒娇
- 在意的约定：会惦记大叔说的明天叫醒/继续聊天
```

（顺带说一句：我第一次查的时候用错了 API（`get_profile` 不存在），
差点得出「画像为空」的错误结论。**查数据前先确认方法名对不对。**）

**改法**：

1. `express()` 新增 `profile_text` 参数，作为独立一段
   **【你记得的关于对方的事】** 注入 system
2. **三处调用全部补上**：`main.py`（回复）、`autonomy/conversation.py`（接话）、
   `autonomy/heartbeat.py`（主动开口）
3. 提示词里明写：**优先问「你记得的关于对方的事」那一段里的东西**，
   并给了正反例（「你不是在弄那个机器人吗」✅ / 「最近怎么样」❌）
4. `profile_text()` 空画像时**返回空串**（原来是返回占位文案，
   会插一段没用的话进提示词）

**实测效果**（注入真实画像后，第一轮就变了）：

```
你：今天好累啊
  小星：巧了，大叔我今早巡逻回来直接睡到晌午，被芹香念了半天
        你那个虚拟机里的机器人，又熬夜搞了？        ← 用了画像！
```

之前**根本不可能出现**这种话。

### 问题 B：不会主动找我

**根因：`cold_streak` 的设计是「永久停」，而且只在你先开口时才重置。**

`suppress.py` 原文：

```python
if cold_streak >= limit + 2:
    return Decision(False, "冷场", f"连续 {cold_streak} 次主动未获回复，暂时不再打扰")
```

而 `cold_streak` 的唯一重置点是 `heartbeat.on_user_message()` —— **你说话**。

**后果**：连续 5 次主动没得到回复 → **她再也不会主动找你**，
直到你想起来先跟她说话。而这正是你说的「不会主动找我，除非我一直不理」——
后半句其实**已经实现了，只是实现成了「永久停」**。

另外 `last_spoke_ts` 一直是 0，说明它**从来没主动发过一条**（旧逻辑下几乎不可能触发）。

**改法**：把「永久停」换成你要的**循环**：

| 冷场次数 | 静默时长 |
|---|---|
| 0~1 次 | 不静默（正常聊） |
| 2 次 | 60 分钟 |
| 3 次 | 96 分钟 |
| 4 次 | 154 分钟 |
| 5 次 | 246 分钟 |
| 6 次 | 393 分钟 |
| 8 次+ | **480 分钟（封顶，永不永久停）** |

- 静默期满后，**回来那一句是「关心状态」**，不是继续讲自己：
  提示词要求「以关心对方状态为主」「不要质问（别说你怎么不理我）」
  「可以带一点不安，但别演成委屈」
- **越久不回，静默越久**（`silence_growth=1.6`），这就是你要的「越久越不安」
- 冷场时走固定 `kind=miss`（想起你），不问「有没有可分享的内容」

同时把整体活跃度调高（你说「想让她多说话」）：

| 项 | 改前 | 改后 |
|---|---|---|
| 节奏权重（近/常/远） | 0.25 / 0.60 / 0.15 | **0.45 / 0.42 / 0.13**（偏「近」） |
| 近档间隔 | 20~120 分钟 | **15~90 分钟** |
| 常档间隔 | 2~8 小时 | **1.5~5 小时** |
| 远档间隔 | 12~48 小时 | **7~24 小时** |
| 两次主动最小间隔 | 45 分钟 | **25 分钟** |
| 每日主动上限 | 5 次 | **14 次** |
| 情绪对节奏的影响 | 0.5 | **0.7** |
| 会话窗口 | 15 分钟 | **25 分钟** |

### 测试

离线 **261 项** + 阶段 0 验收 **44 项** = **305 项全过**。

新增「主动性（静默循环）+ 画像进表达通道」9 项，其中三条守的是这次修的 bug：

- ★ **冷场 20 次后仍然允许主动开口**（旧版会永久拦死）
- ★ **静默有上限，不会无限拉长**
- ★ **画像真的进了表达通道的 system**（之前只给了分析通道）
- 冷场后走「关心」类
- 冷场时间隔被拉长（70 分钟还不够）
- 不传画像时不出现空段落

**踩的坑**：断言 `"你记得的关于对方的事" in prompt` 时**撞上了提示词正文里的同一句话**
（我在提示词里也写了这一句），导致误判。改成断言带【】的完整标题。
——**断言用词与提示词正文重名会互相干扰。**

## 第三轮：三个问题的逐条核对（附运行证据）

### ① 时间节奏：改成「随时会来」

**之前**：只有三档，最早 **15 分钟**起（后来我改成 20 分钟）。
体感是「定时任务」，不是「随时可能来一句」。

**现在加了第四档「马上」**（`instant: [1, 8]` 分钟），权重 0.30：

```
马上 [1, 8]    分钟  权重 0.30   ← 新增：忽然想起你，立刻冒一句
近   [20, 120] 分钟  权重 0.32
常   [120, 480]分钟  权重 0.27
远   [720, 2880]分钟 权重 0.11
```

**400 次抽样实测分布**：

| 分位 | 间隔 |
|---|---|
| 1% | 1.3 分钟 |
| 10% | 3.0 分钟 |
| 25% | 6.8 分钟 |
| **50%（中位）** | **83 分钟** |
| 75% | 340 分钟 |
| 99% | 2742 分钟 |

**★ 8 分钟内就来的比例：29%** —— 这就是「可能马上就来」。
同时中位 83 分钟、最长接近 2 天，也就是「也可能晚点再来」。

### ② 自主浏览分享：**之前基本等于没实现，现在实测通了**

**之前的三个问题**：
