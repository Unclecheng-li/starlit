## ③ + ④ 不主动找我 / 不主动分享 —— 同一个根因

### 先看证据（这次终于有确凿数据）

```
last_spoke_ts            = 0          ← 她从来没主动发过一条
digest_share_2026-10-14  = 1          ← 搜到了并产出了可分享项
last_share_ts            = 0          ← 但从来没发出去
digest_last_item         = {topic: 鲸鱼, score: 0.496, ...}
```

**搜到了、额度扣了、一条都没发出去。**

### ④ 的原因：额度在「产出」时就扣了

```python
# digest.run_once 里原来是：
if self.store.counter_get(key) >= self._daily_max:
    return None
self.store.counter_set(key, self.store.counter_get(key) + 1)   # ← 产出就扣
```

而 `mark_shared()`（真正发出后才调的）才该扣。于是：
**产出 → 额度扣光 → 后面发送被拦/心跳没到点 → 这条永久丢失。**

**改法**：

1. 产出时**只暂存**（`digest_pending`），不扣额度
2. 下次进来如果还有 `pending`，**直接把它交出去重试**，不再重新搜（否则每 90 分钟覆盖一次，永远发不出）
3. `mark_shared()`（发送成功后调用）才扣额度 + 清 pending + 记 `digest_history`

### ③ 的原因：上线问候被「有话可说」层拦了

日志原文：

```
[拦截@有话可说] 刚问完对方香干口感，还没得到回应，此刻没有新的想说的内容
```

**两层问题**：

**a. 上线问候不该受这一层管** —— 你明确要求「每次上线都一定发」。
新增 `force_go=True`：跳过第⑤层「有话可说」和第⑥层「送出前复核」。
（但**免打扰、电量这类硬约束仍然生效** —— 半夜启动不会吵你。）

**b. 「有话可说」这层本身太保守** —— 提示词里原来写着：

> 宁可不说，也不要发没营养的消息

这句话让模型极度倾向闭嘴。改成：

> ⚠️ **但要偏「想说」，别偏「不说」**：你是个话多、爱搭话的性子，
> **绝大多数时候都该 speak=true**。
> 「刚问完对方一件事、还没得到回应」**不是**不说话的理由 —— 想到别的就说别的。
> **默认是开口，只有确实没话时才闭嘴。**

实测（同一条上下文）：

| | 改前 | 改后 |
|---|---|---|
| 刚问完话、无外部内容 | speak=**false** | speak=**true**（kind=mood） |
| 有外部内容 | speak=**false** | speak=**true**（kind=content） |

另外上线问候的等待时间也从 **60 秒**放宽到 **60 分钟**
（NapCat 要弹 UAC + 扫码，一分钟根本连不上，原来超时就放弃）。

## ① 表情包去掉最小间隔

```yaml
min_gap_min: 0     # 原来 10 分钟
```

理由你说得很对：**真人上句下句都带表情包很正常**，卡时间反而假。
发不发完全交给语境判断（对方是不是在认真说事、情绪够不够）。

保留了一条：**「上一条正好是纯图」仍然拦** —— 那不是时间问题，是重复。

## ② 人设不够强 / 太人机 / 情绪不明显

### 我先看了当前输出的实际问题

改之前的输出是这样的：

```
你：我昨晚情绪崩溃了，哭了一晚上
星野：啊，昨晚的。大叔这会儿才知道。哭一整宿……眼睛肿了吧，现在好点没。

你：我今天被导师骂了，觉得自己很没用
星野：被骂就被骂了呗，大叔我以前脾气冲得很，现在不也混成个每天睡午觉的。
      不过「觉得自己没用」这话大叔不爱听啊。
      骂你哪件事，活儿没干好，还是他自己心情差找人撒气？
```

**不算烂，但"太稳"了**：每条都完整、都二三十字、都同一个语气、信息量均匀。
对比你朋友的真实消息（「笑唏了，一模一样」「爆爆爆」「绝望」）
和赤川（「睡觉了喵」「盲猜你喝的东西带提神的」）——
**他们的消息都很短、有断点、有情绪尖峰。**

**完整工整本身就是最大的破绽。**

### 改法：用对比示例，不讲道理

在 `persona.md` 新增「说话的节奏」一节，全是 **❌ / ✅ 对照**：

| 你 | ❌ 改前 | ✅ 改后 |
|---|---|---|
| 我昨晚情绪崩溃了 | 「啊，昨晚的。大叔这会儿才知道。哭一整宿……眼睛肿了吧，现在好点没。」 | 「啊？」<br>「哭了整宿？」 |
| 被导师骂了，觉得自己很没用 | 「被骂就被骂了呗，大叔我以前…不过…」 | 「骂你什么了」<br>「后半句收回去。」<br>「大叔不认。」 |
| 哈哈哈哈哈太蠢了 | 「笑成这样也不发过来看看…是猫还是狗？」 | 「发过来啊」<br>「大叔躺着没事干呢」 |
| 嗯 | 「就一个「嗯」啊，大叔还以为你睡过去了呢…」 | 「嗯什么嗯」 |

加上硬约束：**大部分消息 15 字以内**、允许不完整、允许只回几个字。

### 实测效果

| | 改前 | 改后 |
|---|---|---|
| 平均每条长度 | 20~35 字 | **7 字** |

```
你：我昨晚情绪崩溃了，哭了一晚上
星野：啊？
星野：哭了整宿？
星野：……大叔昨晚在巡逻，没看手机
星野：现在呢，还哭不

你：我今天找到工作了！
星野：行啊你
星野：哪家啊，深圳那个？
星野：大叔刚躺下，这消息比午觉提神

你：嗯
星野：嗯什么嗯
```

提示词末尾也压了四条铁律（离生成最近，权重最高）：
短 / 允许不完整 / 允许长短不一 / 别解释。

## 测试

离线 **312 项** + 阶段 0 验收 **44 项** = **356 项全过**。

本轮新增：

- 最小间隔 0 时刚发过也能再发；但「上一条是纯图」仍拦
- **产出分享不扣额度**；发出后才扣；未发出时会复用 pending；发出后清 pending + 记历史
- **强制开口跳过「有话可说」层**；但**电量太低时硬约束仍生效**
- 上线问候默认开启

**踩的坑**：分享那条断言一开始用的是真实打分（0.435 vs 阈值 0.42，勉强过线），
测试文案稍改就掉下去了 → 断言很脆。改成把阈值设为 0，专测额度逻辑。

## 需要你配合的一件事

```bash
专属AI伴侣/companion/data/companion.log
```
