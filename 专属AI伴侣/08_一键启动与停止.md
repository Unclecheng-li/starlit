# 一键启动 / 一键停止

> 本轮（10-13 傍晚）新增。之前的 `.bat` 太多、还容易重复启动，现在合成两个。

---

## 用哪两个

放在 `vol\` 根目录：

| 双击 | 干什么 |
|---|---|
| **`一键启动.bat`** | 按顺序拉起：搜索实例 → 伴侣服务 → QQ 通道 |
| **`一键停止.bat`** | 只停「搜索实例」和「伴侣服务」，**不动 NapCat / QQ** |

## 一键启动会做什么

```
============================================================
  Vol 一键启动
  顺序：搜索实例  ->  伴侣服务  ->  QQ 通道
============================================================

[1/3] 搜索实例 SearXNG ...
      已在新窗口启动：Vol - 搜索
      已就绪

[2/3] 伴侣服务 ...
      已在新窗口启动：Vol - 伴侣
      已就绪

[3/3] QQ 通道 NapCat ...
      启动中 —— 会弹管理员权限窗口，点「是」，然后用手机扫码

============================================================
  三个窗口：Vol - 搜索 / Vol - 伴侣 / Vol - QQ通道
  都别关。要全停就双击「一键停止.bat」
============================================================
```

**每一步都会先探测端口，已经在跑就跳过。** 这样就不会再出现你这个报错：

```
OSError: [Errno 10048] ... 6701 ...
```

三个窗口的标题分别是 `Vol - 搜索` / `Vol - 伴侣` / `Vol - QQ通道`，都别关。

## 一键停止会做什么

```
============================================================
  Vol 一键停止
  只停「伴侣服务」和「搜索实例」两类 python 进程
  NapCat / QQ 不会被关（那是你的 QQ，手动关就行）
============================================================

  已停止 伴侣服务（PID 7272）
  已停止 搜索实例（PID 13496）

  共停止 2 个进程。
```

**为什么不用 `taskkill /IM python.exe`**：那会把你机器上**所有** python 进程都杀掉
（编辑器、别的项目、Jupyter……）。所以改成两层：

1. **优先读 `vol\run\*.pid`** —— 服务启动时自己写下的 PID，精确
2. 兜底才按命令行特征找（需要 `psutil`，没装就跳过）

**实测**：启动前 python 进程数 2 → 启动后 6 → 停止后 2，**没有误杀别的 python**。

## 端口被占用时会提示什么（不再是一堆 traceback）

以前再启动一个会直接崩出 `OSError: [Errno 10048]`。现在会分辨两种情况：

**情况一：是我们自己已经在跑**

```
==========================================================
启动失败：端口 6701 上已经有一个 Vol 在跑了 —— 这次不重复启动。
  处理办法：双击 vol\一键停止.bat 把旧的清掉，然后再启动；
  或者干脆就用原来那个，不用再开（不影响 NapCat 连接）。
==========================================================
```

**情况二：是别的程序占了**

```
==========================================================
启动失败：端口 6701 被别的程序占用了。
  查看占用者：netstat -ano | findstr :6701
  然后在任务管理器里按 PID 找出来；
  或者改 companion/config.yaml 里的 qq.ws.port（和 NapCat 侧要同步改）。
==========================================================
```

判断依据：本服务在 `/healthz` 上返回 `{"ok": true}`，拿这个当指纹去探测。
退出码是 **3**，不是异常退出。

## 实现说明（怎么做的）

`.bat` 只做三行外壳，**所有逻辑和中文输出都在 Python 里**：

```
vol\一键启动.bat            →  scripts\launch_all.py
vol\一键停止.bat            →  scripts\stop_all.py
vol\start_searxng.bat       →  scripts\run_searxng.py
```

为什么这么拆：
- `.bat` 里写中文有编码坑（cmd 按 GBK 读 UTF-8 文件会把路径读碎）
- 让 Python 打印中文，和 `chcp 65001` 的窗口编码一致，不会乱码
- 端口探测、进程管理用 Python 写清楚得多

**`.bat` 内容保持纯 ASCII**，用通配符定位中文目录：

```bat
for /d %%D in ("%~dp0*") do (
  if exist "%%~fD\companion\scripts\launch_all.py" set "LAUNCH=%%~fD\companion\scripts\launch_all.py"
)
```

## 本轮修掉的 4 个坑（都是实测才发现的）

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | `ROOT` 层级算错（少算一层） | `launch_all` 找不到 `searxng/` 和 `start_napcat.bat`；SearXNG 起不来 | 改成 `parents[3]`（`scripts/` 往上是 4 层才是 `vol`） |
| 2 | `subprocess(text=True)` 按 UTF-8 解 `tasklist` 的 GBK 输出 | 抛 `UnicodeDecodeError` → `alive()` 恒为 False → **一个进程都停不掉** | 显式 `encoding="gbk", errors="replace"` |
| 3 | `urllib` 默认走系统代理 | 探测 `127.0.0.1` 拿回 502 → 误判"没在跑" → 重复启动 | 用 `ProxyHandler({})` 显式禁用代理 |
| 4 | `.bat` 里 `pause` 的提示在 UTF-8 窗口是乱码 | 看着像坏了 | 改由 Python `input()` 等待回车 |

第 2 条最隐蔽：**表面上脚本"跑成功了"，但实际一个都没停**。如果不看进程数变化根本发现不了。
