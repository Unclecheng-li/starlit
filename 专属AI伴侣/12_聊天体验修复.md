# 第四轮：6 个问题的根因与修复

> 你这次给的 6 条，**每一条都追到了具体成因**，其中 3 个是真 bug（会直接影响可用性）。

---

## ① 多发话（情绪场景三轮不够）

**成因**：三个上限写死得太小。

| 项 | 改前 | 改后 |
|---|---|---|
| 一条回复最多拆几条 | 3 | **5** |
| 没等到回复时最多连说几条 | 3 | 3（普通）/ **8（深聊）** |
| 同一话题最多补几次 | 3 | 3（普通）/ **8（深聊）** |

**关键是「深聊」判定**：这轮如果是对方在倾诉 / 需要安慰，
自动把两个上限放到 8。判定依据（任一条成立）：

- `latent_need` ∈ {想倾诉、被安慰、想陪伴、被看见、被认可}
- 检测到风险信号
- `relation_signal > 0.5`

不写死成"永远 8 条"——普通闲聊还是 3 条，免得变刷屏。

## ② 识别不了聊天记录 / 长截图

**这是两个完全不同的问题，凑巧表现都是「打不开」。**

### 2a. QQ 聊天记录（合并转发）—— **完全没实现**

`parse_message` 里根本没有 `forward` / `json` 段的处理，**直接忽略**。
所以你把一整段聊天记录转过来，模型眼里是**空的** ——
它只能回一句"记录要发就发"，非常出戏。

**改法**：

1. `parse_message` 识别 `forward` 段（和 `json` 段里嵌套的 `meta.detail.resid`）
2. 新增 `NapCatChannel.fetch_forward()` —— 调 NapCat 的 `get_forward_msg` 取正文
3. 拍平成 `昵称: 内容` 的文本，拼进 `msg.text`（上限 4000 字）

### 2b. 长截图 —— **图太大被接口拒收**

实测铁证：

```
文件: b19857bf.jpg   1220x19152   1.39 MB
image_complete() → ok=True          ← 图是完整的！
识图调用 → HTTP 400 "unsupported image"
```

**图是好的，但尺寸炸了。** 逐档实测边界：

| 尺寸 | 像素 | 结果 |
|---|---|---|
| 1220x19152 | 23.4M | **✗ 400 拒收** |
| 504x7924 | 3.99M | ✓ 能读 |
| 399x6264 | 2.50M | ✓ 能读 |
| 319x5011 | 1.60M | ✓ 能读 |
| 99x1568 | 0.16M | ✓ 能读，**但字全糊了** |

**踩的坑**：我第一版把上限卡在 1.15M 像素，结果长截图被缩成 99x1568，
宽度只剩 99px —— 模型说"字太小根本看不清"，等于白看。
放宽到 4M 之后：

```
[perceive] 图太大，已缩放：1220x19152 → 504x7924（1423KB → 509KB）
→ 深夜微信聊天截图：一方情绪崩溃、吃醋求安慰，一方冷静讲道理… ✅
```

**教训**：缩小了不等于能看。长图要**保宽度**，否则文字糊掉。

## ③ 电量恒 0 + 突然掉线

### 3a. `[conv] 不接话：社交电量 0 太低` —— 电量只降不升

```python
# apply_interaction 里：
e.energy = _clamp(e.energy - 3.0)     # 每说一句扣 3
```

**而恢复只发生在 `tick()` 里**，`tick` 又只被心跳调用（且要求处于免打扰时段）。
→ **聊天时电量只降不升**，一路到 0 → 会话层每次都被"电量太低"拦掉 → **再也不接话**。

实测当时的数值：`energy=0.0`，而 `valence=96.8 / arousal=100`（另一个 bug，见 ⑤）。

**改法**：电量随互动质量变化 —— **聊得投入会回血，敷衍才掉电**：

```python
e.energy = _clamp(e.energy - 1.5 + 2.5 * q)
# q=0.9 → +0.75（回血）   q=0.5 → -0.25   q=0.1 → -1.25
```

另外加了个去重：**同一条拦截原因不重复刷日志**（原来每 60 秒刷一行，实测刷了几十行）。

### 3b. 突然掉线 —— `_ws_handler` 漏了 `return ws`

```
Missing return statement on request handler
AttributeError: 'NoneType' object has no attribute 'prepare'
```

`_ws_handler` 结尾**没有 return**，aiohttp 内部拿不到响应对象就报错，
表现就是**用着用着突然断连**。已补上。

## ④ 多条消息逐条回 + 表情包每条都回

### 4a. 连发几条 → 应该合并成一次回复

**原来**：来一条处理一条。你连发 5 条（真实记录里 22:58:08 → 22:58:45 就发了 6 条），
她会回 6 次，而且**每条都只看得到自己前面那一条**，完全没有上下文。

**改法**：加了 debounce 合并队列。

- 收到消息先攒着，**最后一条之后等 3 秒**再统一处理
- 第一条最多等 14 秒（防一直等不到静默）
- 一次最多合并 10 条
- 合并时文本拼接、图片 / 转发 id 汇总

```
[main] 合并 6 条消息为一次回复
```

（`merge_window_sec: 0` 可关闭，测试里就是这么关的。）

### 4b. 纯表情包不用每条都回

**改法**：只甩表情包（没文字）时，**只有 25% 概率回**。

**这里踩了个坑**：我第一版判定写成「没文字 + 有图 = 表情包」，
结果**把用户发的聊天记录截图也当成表情包跳过了**。
截图也是没文字的。

修正后**必须要有正面证据**才算表情包：

- 段类型是 `mface` / `marketface`（商城表情）
- `sub_type == "1"`（自定义表情）
- `summary` 含「动画表情」

**没有这些标记的普通 image 段，一律当正经内容处理。**

## ⑤ 感受不到情绪，太平太冰冷

**两个成因叠加。**

### 5a. 数值顶格 → 情绪永远"开心"

```python
# 原来：
e.valence = _clamp(e.valence + 30.0 * (q - 0.5), -100, 100)
```

`quality` 常年 0.8~0.9 → **每轮 +9~12**，而回落只有 0.12/小时。
→ 一天之内就顶到 100 不动了。实测：`valence=96.8, arousal=100`。
`mood_label()` 于是永远输出「开心」，`describe()` 喂给模型的就是一句死板的心情。

**改法**：改成**朝目标渐进**，天然有上限、也能回落：

```python
v_target = 60 * (q - 0.5) * 2          # q=1→+60, q=0.5→0
e.valence = _toward(e.valence, v_target, ...)   # 朝目标逼近
```

### 5b. 提示词没要求把情绪写出来

新增一段「**别把情绪咽下去**」：心情好就让语气轻快、累就说累、
烦就叹气；用语气和节奏传情绪（敷衍的"哦"、无奈的"行吧"、懒得解释的"算了"）；
允许突然提高音量、嘟囔、没好气。
但补了一句"别演过头 —— 情绪是底色，偶尔才浮上来"。

## ⑥ 从不主动找我 → 上线必发

**改法**：新增**上线问候**。

- 服务启动后等 20 秒（留出连 NapCat 的时间）
- 等 NapCat 连上（最多等 60 秒）
- 然后**强制**发一条主动消息（`poke_once(force=True, kind="miss")`）
- 免打扰时段会跳过（不然半夜启动会吵你）

配置：

```yaml
greet_on_start: true
greet_delay_sec: 20
```

## 测试

离线 **299 项** + 阶段 0 验收 **44 项** = **343 项全过**。

本轮新增 16 项，覆盖：

- 普通图片（截图）**不算**表情包 → 会回
- `sub_type=1` / `mface` 算表情包 → 可跳过
- 带文字的**不算**纯表情包
- 多条消息合并（文本拼接、转发 id 汇总、计数）
- `forward` 段 / `json` 段（嵌套 resid）都能取到 id
- 超长图会被缩放，且**不超像素上限 / 最长边上限**
- **正常尺寸的图原样不动**（不该被误缩放）
- 深聊上限 > 普通上限
- 电量语义：聊得投入回升、敷衍下降、**不会因聊天掉到 0**

**踩的坑记录**：

1. **缩小 ≠ 能看**。第一版把长图缩到 99x1568，宽度不够，字全糊。放宽到 4M 像素才对。
2. **"没文字 + 有图"不能判定为表情包** —— 截图也符合这个条件，会被误跳过。
3. 加 `parse_message` 第 6 个返回值后，**测试里 8 处解包全挂了**。
   改函数签名必须全局搜调用点（这已经是第二次踩）。
4. 测试的临时配置要显式关掉 debounce，否则 `handle()` 只是入队就返回，
   断言在回复到达前就跑完了（假失败）。
